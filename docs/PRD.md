## 一句话需求

Chopstory 是外国人在中国餐厅的店内用餐伙伴：拍一张中文菜单，它变成一份「读得懂、点得对、吃得明白」的菜单。

我们优化的是**外国人到店就餐的整体文化饮食体验**，两个价值点：一是对菜品有更深的理解——吃懂每道菜，而不只是翻译菜名；二是一套顺畅的点餐下单流程——看懂菜单 → 放心下单 → 与服务员交互 → 吃懂文化 → 留下可分享的美食足迹。场景只有一个：**线下到店点单**。

## 用户心智、故事

（Jake：美国游客，对花生过敏，怕辣，第一次来成都）

1. 坐下翻开全中文菜单，服务员就站在旁边。我拍了一张，十几秒后每道菜变成我看得懂的卡片——「抄手」不再是 "Copying Hands"，「钵钵鸡」不再是 "Bowl Bowl Chicken"，凉拌菜里藏着的花生被红字标了出来。**它替我操心了我不知道该操心的事。**
2. 选好菜进入点单页，一键切到服务员视图，把手机递过去：中文大字菜名 + 「我对花生过敏，请不要放入我的食物中」，服务员点头下单。我还照着卡片上的拼音把「chāo shǒu」念了出来。**第一次在中国点菜没靠比划，甚至体验了一把「本地人式沟通」。**
3. 饭后我知道了钵钵鸡为什么叫钵钵鸡，讲给同桌朋友听。我的 Food Map 上多了一颗钉——离开中国时，我带走一张「47 道菜 · 3 个城市」的地图。**这顿饭变成了我的社交资产。**

## 定位和用户价值

**真实痛点**（全部有出处，详见 `research/foreign-diner-insights.md`）：


| 痛点             | 证据                                                          | 打的是我们哪一步                     |
| -------------- | ----------------------------------------------------------- | ---------------------------- |
| 看不懂：翻译了也不知道是什么 | 直译菜名完全不可解；连海外华人都说「知道夫妻肺片里没有肺，但还是不知道这道菜到底是什么做的」              | 看懂菜单：解读式菜品卡                  |
| 不敢点：选择集萎缩      | r/travelchina「中国菜单太难」求助帖 441↑；有游客整趟中国行每晚吃同一个烧烤摊——不是不想换，是不敢点 | 放心下单：忌口折叠 + 雷点 tag（对应心智故事 2） |
| 吃出事：过敏原藏在暗处    | 素菜用蚝油提鲜、酱油含麸质、凉拌菜里藏花生；有甲壳类过敏游客发帖求中文过敏卡（90↑）                 | 过敏红标 + 点单卡过敏警示盒              |
| 沟通难：服务员站在旁边催单  | 口头说过敏无效，社区最佳实践是把打印好的中文卡直接递给后厨                               | 服务员视图 + 菜名发音                 |


**优势场景**：我们只打「线下到店点单」这一个场景，并把目标定在文化体验的深度——用户吃完不只是吃饱了，而是更懂中餐了。

和「拍照问 GPT」的区别，是我们把文化 gap **提前封装**进了产品：

1. **菜名解读**：抄手、钵钵鸡、夫妻肺片这类菜名直译必坏（Google Translate 出来完全不可解，用户还得逐道追问 GPT）。我们预置译法与解释策略：译名一眼懂 + 一句话消除恐惧 + 文化由来（吃完还能讲给别人听）。
2. **按西方菜单习惯组织信息**：老外的母国菜单自带成分描述、过敏原图标、辣度标识（法定 + 行规基线），中国菜单只有菜名 + 价格。我们把 ingredients、过敏原、忌口雷点、辣度按他们熟悉的坐标系补齐并 highlight——包括他们想不到中国菜里会有的成分（蚝油提鲜、猪油炒菜、酱油含麸质）。
3. **全流程小细节堆出「被照顾感」**：价格双显换算、过敏原红标、忌口折叠、服务员点单卡。亮点不靠一个大功能，靠每张卡的解读质量和细节。

**明确不做：菜单内重排 / 个性化推荐。** 个性化的杠杆在「找店」维度；店确定后菜单已收敛，重排空间小。决策留给用户，我们负责把信息给全、给对。

## 竞品信息


| 类别    | 产品               | 没解决什么                                                    |
| ----- | ---------------- | -------------------------------------------------------- |
| 翻译工具  | Google Translate | 直译必坏：金丝肥牛 → "Golden Thread Fat Cow"，抄手 → "Copying Hands" |
| 通用 AI | ChatGPT / Gemini | 每道菜要逐个追问，使用成本高；无结构化菜单视图                                  |


**结论**：翻译层已经不稀缺，没人把「店内用餐全流程」封装成一个产品体验。这就是我们的位置。

### S0 首页：上 1/3 拍菜单引导，下 2/3 社交资产（✅ 已在原型落地，本轮重构）

- **上 1/3**：品牌 + slogan「Taste China, order like a local.」（2026-07-12 定稿，见「品牌定名」节）+ 一个主 CTA「📷 Scan a menu」+ 次按钮「🖼️ Album」+ 画像 chips 条。砍掉了旧版大相机圆钮与重复的双入口（占屏挤压社交资产）
- **下 2/3「MY FOOD STORY」**（参考 `bellybook-home-recent-eats.png` 胃之书）：
  - **迷你食迹地图直接上首页**（中国风宣纸底，吃过的省整块点亮，样式规范见 UI-DESIGN.md），点击进全屏地图
  - 下接 Recent 时间线：日期分组（Today · Chengdu）→ 斜贴拍立得 + 店名 + 「N dishes scanned · M ordered · ¥合计≈$」+ 一句高光记录 + 时间。点卡回到当次菜单
  - 空态：还没有记录，快去拍第一张菜单吧
- **两种扫描入口的行为**：拍照 → 相机取景（demo 里对准 mock 菜单纸）；**从相册选 → 跳过取景直接进识别，用真实菜单照片**（`public/real-menu-mawangzi.jpg`，View original 也显示照片）。识别一次产出全部卡片数据（含详情页字段），详情页零二次加载
- 相机与识别中两屏：
  - 相机取景：对准框四角 + 顶部提示「将菜单对准框内」+ 底部提示「保持菜单平整，光线充足效果更好」
  - 识别中（等待页，很重要——消除拍完没反应的焦虑）：菜单缩略图 + 「正在理解菜单：AI 正在识别这 N 道菜」+ 三步进度清单（图像识别·菜名提取 ✅ → AI 翻译·文化解析 进行中 → 卡片生成 等待中）
  - **整单一次性呈现（✅ 已落地，替代逐条流式）**：识别完成后整份菜单一起出现（卡片 0.6s 内级联入场），给用户「这是你的完整菜单」的确定感——逐条蹦出的体验被否了。真实 API 接入后策略：后端仍流式返回，前端攒齐再一次性呈现（进度页的「已识别 N 道」计数消费流式事件）

### S1 菜单 list

识别完成后整单一次性呈现。每道菜一张 preview 卡，命中忌口的折叠到底部并标注原因；**底部常驻「My Order」条**（未选菜时也在，文案引导去选菜；已选时显示 N dishes + 双币合计）（✅ 已落地）

- 顶部菜单信息条（餐厅名 · N 道菜 · 查看原图），参考 `menux-list-detail-aichat.jpg` 左一
- **分类 tab（顶部横滑 chips，sticky）**：不照搬原菜单分类直译，而是映射到老外熟悉的标准分类坐标系（= 核心价值第 2 条）：`Cold Starters / Mains / Vegetables / Soups / Rice & Noodles / Dessert / Drinks`。模型输出 `catStd`（标准枚举）+ `catOriginal`（原菜单分类中文，如「经典凉菜」）。菜单上没有的分类不显示 chip；chip 带数量（Mains 12）
- **⭐ Signature 是筛选标签不是分类**：招牌菜仍归属自己的分类，Signature chip 是跨类筛选（依据 = 原菜单「招牌」标记，诚实来源）
- **All 视图 = 平铺 + 分区小标题**：按标准分类分组，组间 section header（英文分类名 + 原菜单分类中文小字）；点 chip = 只看该类。组内排序 = 原菜单顺序，不做重排
- 不做左侧竖排 sidebar（美团点单式）：适合 60+ 道超长菜单但交互重，demo 菜单 14–16 道用不上，P2 再评估

### S2 菜品详情

决定「点不点」+ 交付「吃懂文化」的主阵地。**呈现为底部弹层（bottom sheet）浮在 list 之上**，不是全屏跳转——点卡上滑弹出，蒙层点击 / ✕ 关闭，list 停留在原位（✅ 已落地）。**信息层级原则：先决策，后文化**——桌边停留几十秒，决策字段在前；文化故事放最后，是等菜时慢慢读的加分体验。字段自上而下：

1. hero emoji（刻意不用 AI 生成菜品图：生成图误导实物预期，是红线的延伸）
2. 译名 / 中文名 + 拼音 + 🔊 / **菜系·地区副标题**（"Sichuan · Chengdu classic"，参考 MenuX 的「法国·普罗旺斯」）
3. 价格双显 + 置信度 banner + 个人警示 banner（✅ 已落地）
4. 一段话描述（quote 块）：是什么、怎么做、什么口感，消除恐惧优先（✅ 已落地）
5. **口味 bars（P0，MenuX 样式）**：Spicy 🌶 / **Numbing ⚡ 麻**（独立维度，我们独有——麻婆豆腐「轻微电流」的可视化落点）/ Richness 油腻，0–10
6. Ingredients emoji chips + Allergens（contains 红 / may 黄）+ Heads-up 质地雷点（✅ 已落地）
7. **The story（新小节）**：菜名由来 / 文化背景，Gemini grounding 查证——查得到才有这一节，查不到整节消失，不编（红线）。有吃法讲究的菜（钵钵鸡冷串串、小笼包先开窗）加一行 **How to eat**
8. CTA：Add to order / 数量 stepper（✅ 已落地）

- P1：「给服务员看这道菜」单菜全屏中文卡；Can I customize 提示（微辣可调 / 香菜可免——填补老外「默认可定制」的心智落差）
- P2：AI 追问 chips（见后续功能）

**数据契约新增字段（Kevin）**：`catStd` 枚举、`catOriginal`、`cuisine/region`、`flavorBars{spicy, numbing, richness}`、`story`（nullable，带来源）、`howToEat`（nullable）、`customizable[]`

### S3 点单卡

list 底部常驻「My Order」条 → 点单页（✅ 已落地，「双 tab 唯一切换 + 三段式」结构，2026-07-12 定稿；参考 `order-card-dual-view.jpg` 的双视图思路，方向反过来）：

- **顶栏一行**：返回键 + 双 tab 同一行，无独立 title 行；双 tab 是**唯一**切换（无底部大按钮重复同一动作）
- **双 tab 英文命名**（切换引导必须英文——用户看不懂中文）：`For me · English · $` ｜ `For waiter · 中文 · ¥`
- **一次性引导条**（tab 下方，accent 底色，可点击直达）：「Done choosing? Switch to **For waiter** and hand your phone over →」，切换过一次即消失
- **内容三段式，两面板块严格 1:1**（安全感来源，切 tab 只换语言货币、位置不动）：
  1. **开场白气泡**：Hello! I'd like to order… / 您好！我想点以下这些菜 🙏
  2. **菜品卡（容器化 UI 元素，自带空态）**：非空 = 菜品行（For me：英文名大字 + 中文/拼音小字 + ≈$；For waiter：中文大字 + 英文小字 + ¥）；**Total 弱化为容器底部小字**——合计是给顾客看的，服务员要看的是菜名。空态 = 🍽️ + 「No dishes yet」+ Browse the menu 按钮，放在容器内（页面结构不因空态改变）
  3. **注意事项卡（Heads-up for the kitchen，容器化）**：⚠️ Allergies / 🙅 Avoid / 📝 Requests / 💬 自由备注 四行，**每行有自己的空态**（None set — tap Edit）；**整卡一个 ✎ Edit 按钮**——编辑态内过敏 chips、忌口 chips、备注 chips 全部可改，外加自由文本输入（真实版由 Gemini 翻成中文），Done 保存并回写画像（list 忌口折叠联动刷新）。For waiter 面同位置显示中文三行（过敏红字加重），无 Edit
- **底部双语点菜卡说明**（两面同一块，给用户和服务员同时看）：EN「This is an order card — the guest's picks, translated into Chinese.」+ CN「这是一张点菜卡：顾客已选好以上菜品，请您确认后下单，谢谢！」

### S4 历史记录（P1）

拍过的菜单、点过的菜自动留档，收藏感。两层做法：

- 实用层，参考 `menushot-history.jpg`：历史按「时间 + 地点」分组（列表：2026年7月15日 下午3:44 · 中国, 北京），点进单条 = 地点地图缩略图 + 订单历史（菜名双语 + 价格 + 数量）+ 「查看完整菜单」，左滑删除
- **美食足迹地图（✅ 已在原型落地）**，参考 Pocket Earth 三张图 + 胃之书：**真·中国地图**（技术选型：Apache ECharts + 阿里 DataV 免费 GeoJSON，CDN 懒加载、无 key 无构建；断网回退 CSS 假地图）
  - 浅暖灰省份底图 + 主要城市小灰点（未访问）；**吃过的城市用陶土橙涟漪点亮** + 城市名标签
  - 点击点亮的城市 → 弹出拍立得卡片：那顿饭的照片（emoji 占位）+ 店名 + 「N dishes · ¥消费 ≈ $」+ 日期
  - 顶部计数「MY FOOD MAP · DISHES: 8 · CITIES: 2 / 34」；支持拖拽/缩放
  - 定位用浏览器 geolocation，拿不到就手动选城市。**demo 和小红书传播的记忆点**

## 菜品卡（两级）

**Preview 卡（list 里）**——一眼扫过做初筛。字段结构参考 `menushot-preview-card-fields.jpg`（MenuShot 的标注图，它有：图片/原名/读音喇叭/译名/原文/译文/价格/数量加减）：


| 字段               | 说明                                                                              |
| ---------------- | ------------------------------------------------------------------------------- |
| 译名               | 准确、易懂（主标题）                                                                      |
| 中文名 + 拼音 + 发音小喇叭 | 小字                                                                              |
| 价格双显             | **$ 为主、¥ 为辅**（≈ $12 大字 + ¥88 小字；静态汇率标 approximate）。用户视图一律 $ 优先；服务员视图只显 ¥（✅ 已落地） |
| 辣度               | 🌶 0–3，按西方人基线校准                                                                 |
| 警示 tag           | 见下方规则，最多 2 个                                                                    |
| ＋                | 加入点单                                                                            |


**Preview 卡进哪些 tag（已确认的规则）**：只进「一眼决定跳过这道菜」的信息，优先级排序取前 2 个：

1. 🔴 命中我的过敏原/忌口（个人化，最高优先级，同时触发折叠）
2. ⚪️ 通用雷点：内脏 / 整鱼头 / 带骨 / 肥肉（老外普遍在意，不分个人）
3. 🌱 素食友好（有则展示）

其余维度（may_contain、口感、文化说明）一律留在详情卡，preview 不堆 tag。

**详情卡（点开后）**——先决策，后文化（字段顺序即页面顺序，详见 S2）：


| 字段                 | 说明                                                    |
| ------------------ | ----------------------------------------------------- |
| 译名 + 读音            | 拼音带声调 + 🔊，可读给服务员                                     |
| 菜系·地区副标题           | "Sichuan · Chengdu classic"，一行字立住文化感                  |
| 价格双显 + banner      | 置信度「Not sure」/ 个人警示，命中才显示                             |
| 一段话描述              | 是什么、怎么做的、什么口感；文化菜名要消除恐惧（夫妻肺片 ≠ 肺）。样式：引用块              |

| Ingredients        | 主要成分 3–5 个，emoji chips                                |
| 过敏警告               | contains（红）/ may contain（黄），不滥标                       |

## 红线场景（Don'ts，不可删改）

点菜是即时消费，过敏是安全问题——错一次，信任归零。


| 负向场景         | ❌ 负向示例                            | 核心原则                                                                |
| ------------ | --------------------------------- | ------------------------------------------------------------------- |
| 编造菜品         | 照片第 7 道菜模糊识别不出，模型顺手补了一道「宫保鸡丁 ¥38」 | **识别不出就不出卡。** 宁可少一道，不可错一道                                           |
| 过敏原滥标        | 为求稳给所有菜都标 may contain peanuts     | 滥标 = 狼来了，真警告失效。contains（红）/ may contain（黄）分开，页面常驻免责声明（花生油/芝麻油提示）    |
| 过敏原漏标 / 假装确定 | 「清炒时蔬」标成 vegan，没提可能用蚝油提鲜          | 拿不准就 may contain + 显性标 "Not sure about this one"。**标错是安全事故，不是 bug** |
| 文化解读编故事      | 查不到钵钵鸡的由来，编一个民间传说凑数               | 查得到才讲；查不到只讲「是什么、怎么吃」                                                |
| 数字装精确        | ¥88 = $12.31                      | 静态汇率 + 标 approximate；价格一律 as reported                               |
